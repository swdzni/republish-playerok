# Playerok Free Republisher

Отдельный скрипт, который следит **только** за ID из `items.txt`. Он не меняет
название, цену, описание, картинку, категорию и другие поля товара. Когда товар
становится `SOLD`, `EXPIRED` или `DRAFT`, скрипт перевыставляет этот же товар через
бесплатный статус `DEFAULT`.

Premium защищён двумя проверками: перед публикацией скрипт запрашивает актуальные
варианты у Playerok и принимает только `DEFAULT` с ценой `0 ₽`; после ответа он
проверяет, что сайт вернул `DEFAULT`. Если бесплатного варианта нет, публикация
останавливается с понятной ошибкой.

Если Playerok добавил к категории новую обязательную характеристику, старый проданный
товар может ответить «заполните все обязательные характеристики». В этом случае скрипт
один раз пересохраняет уже имеющиеся опции товара и добавляет только явно настроенные
значения из `missing_attribute_defaults`. Для текущей категории задано
`region=global`. Название, цена, описание, картинка и данные товара не передаются в
`updateItem` и не меняются.

## Быстрый запуск Windows

1. Установите Python 3, если его ещё нет.
2. Дважды нажмите `run_windows.bat`. При первом запуске окружение и зависимости
   установятся автоматически, а рядом появится `.env`.
3. Откройте `.env` и вставьте всю строку cookies Playerok в `PLAYEROK_COOKIES=`.
4. В `items.txt` вставьте ID, ссылки или slug товаров — по одному на строку.
5. Снова запустите `run_windows.bat` и оставьте окно открытым.

## Быстрый запуск macOS

1. Установите Python 3.
2. Откройте Terminal в папке проекта и один раз выполните:

   ```bash
   chmod +x run_macos.command
   ```

3. Запустите `run_macos.command`. Первый запуск сам создаст `.venv`, установит
   зависимости и создаст `.env`.
4. Заполните `.env`, затем `items.txt`, и снова запустите файл.

Поддерживается системный Python 3.9 из macOS Command Line Tools. Для него проект
использует `urllib3` 1.26, совместимый с системным LibreSSL; предупреждения
`NotOpenSSLWarning` после обновления зависимостей быть не должно.

Можно также всегда запускать из терминала:

```bash
python3 launcher.py
```

## Что заполнять

`.env` содержит только подключение Playerok:

```dotenv
PLAYEROK_COOKIES=ваша_полная_строка_cookie
PLAYEROK_USER_AGENT=
PLAYEROK_PROXY=
```

User-Agent и прокси необязательны. Если используете их, cookies, IP/прокси и
User-Agent должны соответствовать одной браузерной сессии.

`items.txt`:

```text
1f1b2592-43bf-6a60-de04-b2be340b9620
https://playerok.com/products/e2986a399499-nazvanie-tovara
e2986a399499-nazvanie-drugogo-tovara
```

Можно смешивать полный UUID, полную ссылку Playerok и slug из конца ссылки. Файл
перечитывается раз в 30 секунд: товары можно добавлять и убирать без перезапуска.
Повторы автоматически удаляются, а после загрузки товара отдельно проверяется,
что он принадлежит подключённому аккаунту.

## Логика статусов

- `APPROVED` — всё хорошо, товар не изменяется;
- `PENDING_APPROVAL`, `PENDING_MODERATION` — ожидание сайта, повторный запрос не отправляется;
- `SOLD`, `EXPIRED`, `DRAFT` — бесплатное перевыставление;
- `DISCONTINUED` — вручную снят с продажи, бесплатно перевыставляется;
- пустой статус с явным `mayBePublished=true` — безопасно определяется как
  `UNPUBLISHED` и бесплатно перевыставляется;
- `BLOCKED`, `DECLINED` — только красная ошибка в логе, автоматическая публикация запрещена;
- чужой ID — ошибка владения, публикации не будет.

При запуске один раз проверяется весь список. Затем основной режим работает по
событиям Playerok: новая оплаченная сделка содержит ID проданного товара, и скрипт
проверяет **только этот ID**, только если он есть в `items.txt`. Постоянного опроса
всех товаров больше нет. Если WebSocket-событие было потеряно из-за обрыва сети,
раз в 15 минут выполняется страховочная сверка всего списка.

`items.txt` перечитывается раз в 30 секунд без запросов к Playerok. Сразу
проверяются только новые строки; уже известные товары повторно не запрашиваются.
Повторная публикация защищена cooldown, чтобы задержка обновления статуса на сайте
не создавала лишних запросов.

## Проверка и диагностика

Проверить один раз без каких-либо изменений:

```powershell
python launcher.py --once --dry-run
```

Один реальный проход и выход:

```powershell
python launcher.py --once
```

Обычный непрерывный режим:

```powershell
python launcher.py
```

В консоли показываются подключённый аккаунт, стартовая проверка, смены статусов,
каждое перевыставление, повторы после временных ошибок и итоговая ошибка, если все
попытки исчерпаны. Полный лог сохраняется в `logs/republisher.log` с ротацией.
`state.json` хранит только статусы/время действий и помогает пережить перезапуск;
cookies туда не записываются.

Основные параметры находятся в `settings.json`. Для обычной работы их менять не
нужно. `reconciliation_interval_seconds` задаёт редкую полную сверку (по умолчанию
900 секунд), `items_reload_interval_seconds` — частоту чтения локального списка без
обращения к сайту. Старый `poll_interval_seconds` оставлен только для совместимости
со старыми конфигами и в событийном режиме не используется. `retry_attempts` задаёт
число попыток, а задержка между ними растёт до `retry_max_delay_seconds`.
После окончательной ошибки конкретный товар ставится на паузу на
`republish_failure_cooldown_seconds` (по умолчанию 5 минут), чтобы не спамить API.

PlayerokAPI неофициальный: при изменении сайта API может потребовать обновления.
Скрипт в такой ситуации прекращает конкретное действие и оставляет подробную
ошибку, но никогда не переключается на Premium автоматически.
